# STACK XML and Maxima Reference Guide

An authoritative cheat sheet for authoring computer-aided assessment questions in Moodle STACK XML.

---

## 1. Maxima Functions for STACK

### Randomization Functions
| Function | Description | Example |
| :--- | :--- | :--- |
| `rand(n)` | Random integer in $[0, n-1]$ | `a: rand(5); /* 0, 1, 2, 3, or 4 */` |
| `rand([x1, x2, ...])` | Random element chosen from a list | `k: rand([-3, -2, -1, 1, 2, 3]);` |
| `rand_with_step(min, max, step)` | Random number from arithmetic sequence | `x: rand_with_step(1, 10, 0.5);` |
| `rand_with_prohib(min, max, [p1, p2])` | Random integer between min and max excluding list | `d: rand_with_prohib(1, 6, [0, a]);` |

### Ordering and Canonical Display
- `ordergreat(x, y, z)` / `orderless(x)`: Sets term ordering for polynomials and expressions so variables render in the desired mathematical order.
  ```maxima
  ordergreat(x);
  p: a*x^2 + b*x + c;
  ```

### Controlled Simplification (`simp:false` & `ev(..., simp)`)
By default, Maxima immediately simplifies arithmetic and algebraic operations (e.g. $2/4 \rightarrow 1/2$, $x + 2x \rightarrow 3x$). In STACK, to present unreduced fractions, factored forms, or unexpanded expressions to students:

```maxima
/* Turn off automatic simplification in question variables */
simp: false;

/* Define unsimplified fraction or arithmetic */
n: 2;
d: 4;
f_unreduced: n / d; /* stays 2/4 */

/* Selectively simplify where desired */
f_reduced: ev(f_unreduced, simp); /* evaluates to 1/2 */
tans: ev(f1 + f2, simp);
```

> **Warning**: When `simp: false`, even `1 + 1` remains `1 + 1`. Always wrap final algebraic answers with `ev(..., simp)` when constructing model solutions (`tans`).

## 2. CASText2 Markup

CASText2 is STACK's templating language embedded within HTML fields (`<questiontext>`, `<generalfeedback>`, `<truefeedback>`, etc.).

### Expression Tags
| Tag | Purpose | Example | Output |
| :--- | :--- | :--- | :--- |
| `{@expr@}` | Evaluates Maxima expression and typesets as LaTeX | `\[ {@f1 + f2@} \]` | `\[ \frac{3}{4} \]` |
| `{#expr#}` | Evaluates Maxima expression and outputs raw value / string | `<input size="{#boxsize#}">` | `<input size="15">` |

### Block Placement Tokens
- `[[input:ans1]]`: Replaced by the student input widget for input `ans1`.
- `[[validation:ans1]]`: Replaced by the validation container showing the parsed interpretation of the student's entry or syntax errors.
- `[[feedback:prt1]]`: Replaced by the feedback generated by Potential Response Tree `prt1`.

### Generating 2D Plots with `plot()`
STACK supports dynamic gnuplot image generation in SVG format:

```maxima
/* In questionvariables */
f(x) := a*x^2 + b*x + c;
p1: plot(f(x), [x, -5, 5], [y, -10, 10], 
         [box, false], [grid, true], 
         [xlabel, "x"], [ylabel, "y"]);
```

In `<questiontext>`:
```html
<p>Consider the function plotted below:</p>
<p>{@p1@}</p>
```

## 3. Input Widget Types

Define inputs inside `<question>` using `<input name="...">`:

### 1. `algebraic`
Standard mathematical expression input (default).
```xml
<input name="ans1">
  <type>algebraic</type>
  <tans>tans</tans>
  <boxsize>15</boxsize>
  <strictsyntax>1</strictsyntax>
  <insertstars>0</insertstars>
  <syntaxattribute>0</syntaxattribute>
  <forbidwords>diff, integrate</forbidwords>
  <requirelowestterms>1</requirelowestterms>
</input>
```

### 2. `numerical`
Accepts numbers, scientific notation, and simple constants (like `%pi`, `%e`).
```xml
<input name="ans1">
  <type>numerical</type>
  <tans>tans</tans>
  <boxsize>10</boxsize>
  <options>allowDecimal</options>
</input>
```

### 3. `matrix`
Renders an editable $M \times N$ matrix grid.
```xml
<input name="ans1">
  <type>matrix</type>
  <tans>tans</tans>
  <boxsize>4</boxsize>
  <options>
    <width>3</width>
    <height>2</height>
    <matrixbrackets>matrixsquarebrackets</matrixbrackets>
  </options>
</input>
```

### 4. `dropdown`
Drop-down menu choice.
```xml
<input name="ans1">
  <type>dropdown</type>
  <tans>correct_choice</tans>
  <options>[["opt1", "Option A"], ["opt2", "Option B"], ["opt3", "Option C"]]</options>
</input>
```

### 5. `radio`
Radio button group (single selection).
```xml
<input name="ans1">
  <type>radio</type>
  <tans>correct_key</tans>
  <options>[["A", "Local minimum"], ["B", "Local maximum"], ["C", "Inflection point"]]</options>
</input>
```

### 6. `checkbox`
Multiple-selection checkboxes. In STACK, answers are mapped to indexed booleans (`ans1_1`, `ans1_2`, etc.).
```xml
<input name="ans1">
  <type>checkbox</type>
  <tans>["A", "C"]</tans>
  <options>[["A", "Odd function"], ["B", "Periodic"], ["C", "Continuous everywhere"]]</options>
</input>
```

## 4. Potential Response Tree (PRT) Answer Tests

A PRT tests student input `sans` against teacher expression `tans`.

| Answer Test | Description | Typical Use Case |
| :--- | :--- | :--- |
| `AlgEquiv` | Tests if `sans` and `tans` are algebraically equivalent (expands/simplifies internally). | General algebra, e.g. $x(x+1) \equiv x^2+x$. |
| `LowestTerms` | Equivalent to `AlgEquiv`, but strictly verifies integers/fractions are reduced. | Fraction arithmetic, integer simplification. |
| `FacForm` | Verifies `sans` is fully factored in terms of target variable. | Factoring polynomials, e.g. $(x-2)(x+3)$. |
| `Expanded` | Verifies `sans` is in expanded polynomial form. | Polynomial expansion, multiplying brackets. |
| `NumAbsolute` | Tests numerical answer within an absolute error tolerance: `abs(sans - tans) <= tol`. | Decimal rounding questions, engineering calculations. |
| `NumRelative` | Tests numerical answer within relative percentage error: `abs(sans - tans)/abs(tans) <= tol`. | Physics/science measurement questions. |
| `NumDecPlaces` | Checks value matches to exact number of decimal places (e.g. 2 dp). | Financial math, statistical tables. |
| `Int` | Tests calculus anti-derivative equivalence with arbitrary constant $C$. | Indefinite integrals $\int f(x)\,dx$. |
| `CasEqual` | Checks literal identity in CAS without simplification. | Exact syntactic checks. |

### PRT Node Structure in XML
```xml
<prt name="prt1">
  <value>1.0</value>
  <autosimplify>1</autosimplify>
  <feedbackstyle>1</feedbackstyle>
  <feedbackvariables>
    <text><![CDATA[
/* Optional intermediate calculations for grading */
diff_ans: diff(ans1, x);
    ]]></text>
  </feedbackvariables>
  
  <node name="0">
    <answertest>LowestTerms</answertest>
    <sans>ans1</sans>
    <tans>tans</tans>
    <testoptions></testoptions>
    <quiet>0</quiet>
    <truescoremode>=</truescoremode>
    <truescore>1.0000000</truescore>
    <truenextnode>-1</truenextnode>
    <trueanswernote>prt1-1-T</trueanswernote>
    <truefeedback format="html">
      <text><![CDATA[<p>Correct answer!</p>]]></text>
    </truefeedback>
    <falsescoremode>=</falsescoremode>
    <falsescore>0.0000000</falsescore>
    <falsenextnode>1</falsenextnode>
    <falseanswernote>prt1-1-F</falseanswernote>
    <falsefeedback format="html">
      <text></text>
    </falsefeedback>
  </node>
  
  <!-- Node 1: Targeted Feedback for unreduced fractions -->
  <node name="1">
    <answertest>AlgEquiv</answertest>
    <sans>ans1</sans>
    <tans>tans</tans>
    <truescoremode>=</truescoremode>
    <truescore>0.5000000</truescore>
    <truenextnode>-1</truenextnode>
    <trueanswernote>prt1-2-T</trueanswernote>
    <truefeedback format="html">
      <text><![CDATA[<p>Your answer is equivalent, but not in lowest terms.</p>]]></text>
    </truefeedback>
    <falsescoremode>=</falsescoremode>
    <falsescore>0.0000000</falsescore>
    <falsenextnode>-1</falsenextnode>
    <falseanswernote>prt1-2-F</falseanswernote>
  </node>
</prt>
```

## 5. Question Tests (`<qtest>`) XML Specification

Every STACK question should specify test cases in `<qtest>` to protect against regressions across randomized seeds.

```xml
<!-- Test Case 1: Model answer passes full marks -->
<qtest>
  <testcase>1</testcase>
  <description>Teacher model solution</description>
  <testinput>
    <name>ans1</name>
    <value>tans</value>
  </testinput>
  <expected>
    <name>prt1</name>
    <expectedscore>1.0000000</expectedscore>
    <expectedpenalty>0.0000000</expectedpenalty>
    <expectedanswernote>prt1-1-T</expectedanswernote>
  </expected>
</qtest>

<!-- Test Case 2: Common misconception (e.g. unreduced fraction) -->
<qtest>
  <testcase>2</testcase>
  <description>Equivalent unreduced answer gets partial credit</description>
  <testinput>
    <name>ans1</name>
    <value>ev(tans * 2 / 2, simp)</value>
  </testinput>
  <expected>
    <name>prt1</name>
    <expectedscore>0.5000000</expectedscore>
    <expectedpenalty>0.1000000</expectedpenalty>
    <expectedanswernote>prt1-2-T</expectedanswernote>
  </expected>
</qtest>

<!-- Test Case 3: Complete wrong answer -->
<qtest>
  <testcase>3</testcase>
  <description>Arbitrary wrong answer</description>
  <testinput>
    <name>ans1</name>
    <value>0</value>
  </testinput>
  <expected>
    <name>prt1</name>
    <expectedscore>0.0000000</expectedscore>
    <expectedpenalty>0.1000000</expectedpenalty>
    <expectedanswernote>prt1-2-F</expectedanswernote>
  </expected>
</qtest>
```
